# Changelog

## 0.0.1 – unreleased
- Spec 001: core-defaults config layer, layer-confined session references, Pydantic config models + JSON Schema export, `pkpipe validate`, effective-config sha256 hash, test layout (unit/integration/e2e, fakes, `live` marker), CI + Pages workflows, Docusaurus site.
- Spec 002: `ModelPort.complete(..., profile)` with `SchemaError`/`ModelUnavailable`/`ContextOverflow`, OpenAI-compatible adapter (json_schema, local validation, retry, fallback, OpenTelemetry spans), `env:` profile resolution, recorded LM Studio fixtures + `ReplayModel`.
- Spec 002 review: context pre-check against the profile `context` (`ContextOverflow` before sending), reasoning output never mined for draft JSON, lone `</think>` handling, truncated text replies are errors, `model.fallback` event also on the fallback span.
- Spec 003: `pkpipe.telemetry` (OTLP-only bootstrap from `OTEL_*`, flow/step/LLM/tool spans with pkpipe attributes, per-flow content capture with scrubbing exporter, security-flag events, metrics, OpenInference/httpx/FastAPI instrumentation), Phoenix compose with auth off, Langfuse docs.
- Spec 003 review: `telemetry.json` config file (validated, layered) feeds the content policy; URL-decoded OTLP headers; no invented metrics URL with a traces-only endpoint; step spans always carry all seven attributes; reranker payloads scrubbed; `tokens_per_second` / learning-time recorders; live LM Studio telemetry tests.
- Spec 004: obsidian-vault FastMCP server (`pkpipe.obsidian`, `mcp_servers/obsidian_vault`): per-tool path allowlists, atomic front-matter-safe note tools, lossless triage file and processing list, sync-conflict detection, loopback-only Streamable HTTP, launchd example.
- Spec 004 review: `update_triage` refuses pipeline changes to the owner's confirm/override and enforces the domain state transitions (`pkpipe.domain.triage.TRANSITIONS`); managed-file protection is case-insensitive (APFS); conflict files are never appended to or moved; `move_note` cannot overwrite a racing destination; the HTTP server validates Host/Origin against DNS rebinding.
- Spec 005: flow engine. Flows are JSON (`flows/*.json`, schema `flow.schema.json`) compiled into LangGraph StateGraphs: conditional/default/error edges, `Send` fan-out with `max_parallel` (default 2), subflows, wait (poll + absolute deadline); step types llm, llm_tools, tool, code, notify, subflow, wait, guard, registered via `@register_step` / `pkpipe.steps` entry points; isolated, datamarked LLM sessions with declared inputs only. Run service with SQLite run table, pinned config snapshots (version now covers prompts/instructions/contexts/schemas) and LangGraph SQLite checkpoints (`pkpipe run <flow>`, `--resume`, `--resume-all`, `pkpipe runs`); APScheduler sync from `schedules.json` (SQLite job store, one instance per flow, coalesced misfires). New ports `ClockPort`, `TracerPort`, `RunStorePort` with fakes; MCP ToolPort adapter; pack flows `triage`, `categorize_item`, `process_released`, `process_item`, `learning_material`, `other_resource`.
- Spec 006: `NotifyPort.send(event, payload, channels)` returning per-channel `Delivery` results, `ChannelNotifier` (routes from `channels.json`, Jinja2 templates `templates/<event>.<type>.md|json` with truncation and a UI link), Discord webhook, Teams workflow (Adaptive Card) and Apprise adapters, `env:` secrets, `notify.send` spans carrying the sending step's attributes, pack templates for the four events; `notify` step passes payload and reports failed channels.
- Spec 004 follow-up: every vault operation (and so every MCP tool) emits a `tool <name>` span (tool name, item id of single-row upserts, row count; never note content); `pkpipe schema` also exports `triage-row` and `processing-list-row` JSON Schemas.
- Spec 013: evaluation framework (`pkpipe.evals`, `pkpipe eval --suite ...`): five levels (deterministic, triage / sessions / judge calibration, flows on a temp vault, security guard + injection + canary, production rates), synthetic datasets in `evals/datasets`, code-first scorers, LLM judge on a different model (gemma-4-12b) with calibration and pairwise A/B, cassettes (`--cassette record|replay`) recorded live against LM Studio for CI, JSON + Markdown reports traced with `eval.run_id`, gates in `evals.json` (only move upwards) and `PublishGate` for the config UI; pack guard patterns extended.
- Spec 015: optional self-improvement cycle: `improvement_extract` (journal `## Improvement` section -> `proposed` backlog rows, local session without tools, statements kept only if verbatim) and `improvement_review` (weekly evidence from journals with verbatim-checked quotes, verdict proposal, system-change proposal notes for the eval gate, `weekly_review` notification) with vault tools `read_notes`, `read_improvements`, `update_improvements` (the pipeline never changes a status), journal flows validated as local only (`egress` MCP flag, loopback model profiles), `improvement` eval suite + `improvement_extract.jsonl`, review session datasets and rubrics, structured session checks (`fields`, `min_items`, `quotes_from`).
- Repository skeleton, ports, triage domain rules, canary helper, layered config loader.
