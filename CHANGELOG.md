# Changelog

## 0.0.1 – unreleased
- Spec 001: core-defaults config layer, layer-confined session references, Pydantic config models + JSON Schema export, `pkpipe validate`, effective-config sha256 hash, test layout (unit/integration/e2e, fakes, `live` marker), CI + Pages workflows, Docusaurus site.
- Spec 002: `ModelPort.complete(..., profile)` with `SchemaError`/`ModelUnavailable`/`ContextOverflow`, OpenAI-compatible adapter (json_schema, local validation, retry, fallback, OpenTelemetry spans), `env:` profile resolution, recorded LM Studio fixtures + `ReplayModel`.
- Spec 002 review: context pre-check against the profile `context` (`ContextOverflow` before sending), reasoning output never mined for draft JSON, lone `</think>` handling, truncated text replies are errors, `model.fallback` event also on the fallback span.
- Spec 003: `pkpipe.telemetry` (OTLP-only bootstrap from `OTEL_*`, flow/step/LLM/tool spans with pkpipe attributes, per-flow content capture with scrubbing exporter, security-flag events, metrics, OpenInference/httpx/FastAPI instrumentation), Phoenix compose with auth off, Langfuse docs.
- Spec 003 review: `telemetry.json` config file (validated, layered) feeds the content policy; URL-decoded OTLP headers; no invented metrics URL with a traces-only endpoint; step spans always carry all seven attributes; reranker payloads scrubbed; `tokens_per_second` / learning-time recorders; live LM Studio telemetry tests.
- Spec 004: obsidian-vault FastMCP server (`pkpipe.obsidian`, `mcp_servers/obsidian_vault`): per-tool path allowlists, atomic front-matter-safe note tools, lossless triage file and processing list, sync-conflict detection, loopback-only Streamable HTTP, launchd example.
- Spec 004 review: `update_triage` refuses pipeline changes to the owner's confirm/override and enforces the domain state transitions (`pkpipe.domain.triage.TRANSITIONS`); managed-file protection is case-insensitive (APFS); conflict files are never appended to or moved; `move_note` cannot overwrite a racing destination; the HTTP server validates Host/Origin against DNS rebinding.
- Spec 005: flow engine. Flows are JSON (`flows/*.json`, schema `flow.schema.json`) compiled into LangGraph StateGraphs: conditional/default/error edges, `Send` fan-out with `max_parallel` (default 2), subflows, wait (poll + absolute deadline); step types llm, llm_tools, tool, code, notify, subflow, wait, guard, registered via `@register_step` / `pkpipe.steps` entry points; isolated, datamarked LLM sessions with declared inputs only. Run service with SQLite run table, pinned config snapshots (version now covers prompts/instructions/contexts/schemas) and LangGraph SQLite checkpoints (`pkpipe run <flow>`, `--resume`, `--resume-all`, `pkpipe runs`); APScheduler sync from `schedules.json` (SQLite job store, one instance per flow, coalesced misfires). New ports `ClockPort`, `TracerPort`, `RunStorePort` with fakes; MCP ToolPort adapter; pack flows `triage`, `categorize_item`, `process_released`, `process_item`, `learning_material`, `other_resource`.
- Spec 006: `NotifyPort.send(event, payload, channels)` returning per-channel `Delivery` results, `ChannelNotifier` (routes from `channels.json`, Jinja2 templates `templates/<event>.<type>.md|json` with truncation and a UI link), Discord webhook, Teams workflow (Adaptive Card) and Apprise adapters, `env:` secrets, `notify.send` spans carrying the sending step's attributes, pack templates for the four events; `notify` step passes payload and reports failed channels.
- Spec 004 follow-up: every vault operation (and so every MCP tool) emits a `tool <name>` span (tool name, item id of single-row upserts, row count; never note content); `pkpipe schema` also exports `triage-row` and `processing-list-row` JSON Schemas.
- Spec 013: evaluation framework (`pkpipe.evals`, `pkpipe eval --suite ...`): five levels (deterministic, triage / sessions / judge calibration, flows on a temp vault, security guard + injection + canary, production rates), synthetic datasets in `evals/datasets`, code-first scorers, LLM judge on a different model (gemma-4-12b) with calibration and pairwise A/B, cassettes (`--cassette record|replay`) recorded live against LM Studio for CI, JSON + Markdown reports traced with `eval.run_id`, gates in `evals.json` (only move upwards) and `PublishGate` for the config UI; pack guard patterns extended.
- Spec 007: triage and release wired end to end: `triage.backlog` (new + older waiting items in the `triage_ready` message and payload), re-triage of open items whose suggested category was removed from the config, de-duplicated `inbox.select_new`, `daily_summary` payload counts; a confirmed item whose category was removed is never re-suggested (its tick would release an unseen category) and is reported with unknown overrides as `invalid` in `triage_ready`, also without new items (`domain.triage.needs_decision`); integration tests on a real vault, e2e `pkpipe run triage` -> owner edits -> `process_released` with a committed replay cassette and a live LM Studio variant.
- Spec 014: config UI and app MCP server (`pkpipe serve`): FastAPI + HTMX UI (triage, runs, config drafts with validate, smoke eval, publish through the spec 013 `PublishGate` to the overlay git repo, diff and validated rollback, new-category form), JSON API, app MCP server (`run_flow`, `list_triage`, `get_run`, owner actions `confirm_item`, `override_item`, `release_quarantine`) on one authenticated listener: loopback/Tailscale bind only, owner and agent tokens, Host allowlist, CSRF/Origin checks, strict CSP, audit log; owner decision writers in `pkpipe.obsidian` and rules in `pkpipe.domain.triage`; datamarked triage text and run errors over MCP, one active run per flow across UI, MCP and scheduler, gate metrics kept with every publish; browser e2e with Playwright.
- Spec 015: optional self-improvement cycle: `improvement_extract` (journal `## Improvement` section -> `proposed` backlog rows, local session without tools, statements kept only if verbatim) and `improvement_review` (weekly evidence from journals with verbatim-checked quotes, verdict proposal, system-change proposal notes for the eval gate, `weekly_review` notification) with vault tools `read_notes`, `read_improvements`, `update_improvements` (the pipeline never changes a status), journal flows validated as local only (`egress` MCP flag, loopback model profiles, re-checked against the environment when each run starts), `improvement` eval suite + `improvement_extract.jsonl`, review session datasets and rubrics, structured session checks (`fields`, `min_items`, `quotes_from`).
- Spec 008: secure fetch. Pack flow `secure_fetch` (URL filter -> web-fetch MCP -> sanitize -> heuristics + injection classifier -> Reader without tools -> code verdict) with step types `fetch`, `sanitize`, `reader` (raw outputs refused as inputs of sessions with tools) and code `secure_fetch.url_check|scan|verdict`; `pkpipe.security` URL filter (deny-list file `security/deny_list.txt`, private networks after DNS incl. numeric forms, size limit), stdlib sanitizer (hidden HTML, comments, zero-width and Unicode tag characters), weighted heuristics; web-fetch MCP server (`pkpipe.webfetch`, one `fetch_page` tool) running Lightpanda and one Playwright + Chromium fallback behind a filtering proxy that checks every request; `ClassifierPort` + classifier adapter (fails closed when missing; replaced by Qwen3Guard + DeBERTa in spec 009); test-only loopback allowance that no config can set; secure-fetch security eval (`secure_fetch.jsonl`, detection 1.0 / FP 0.024 live) and Reader session dataset; fallback rate in the production suite (`--fetch-stats`). Review fixes: redirect hops into the deny-list are flagged (not `http_403`), invalid Reader replies are flagged (`reader_invalid_output`), the per-fetch proxy stops without waiting on hanging connections.
- Spec 012: learning-gateway MCP server (`pkpipe.learning`, `mcp_servers/learning_gateway`; tools `create`, `status`, `link`, `audio`) behind a `LearningBackend` interface with Open Notebook (REST, local Kokoro TTS via Speaches; default), a NotebookLM browser backend (interface + driver protocol only) and a scripted fake; URL filter (`pkpipe.domain.urlfilter`: scheme, private networks, deny list) before any backend call, idempotent `create` per item, 90 minute configurable timeout with recorded failure reasons, SQLite job store, audio download; `learning_material` flow with URL check (`learning.prepare`), audio step and failure reasons; digest-pinned `deploy/open-notebook` compose and an idempotent setup script (`python -m pkpipe.learning.open_notebook_setup`); a URL the gateway refuses (DNS, deny list) quarantines the item (`learning.create_failed`); learning metrics recorded by the gateway; flow evals run the real gateway over the fake backend (six new cases); live test against a real Open Notebook.
- Classifier swap (owner decision, decision record `docs/decisions/0001-injection-classifier.md`): no Meta models; the gated-classifier adapter, its extra and settings are removed. `security.classifier {backend, model, model_dir, chunk_tokens, members, threshold, required}` with Qwen3Guard-Gen-0.6B (official weights, `Safety:`/`Categories:` parsing, label-probability score, token chunks, no remote code), ProtectAI deberta-v3-base-prompt-injection-v2 (vetted safetensors, SHA-256 checked) and a `combined` (max) backend; extra `guard`; measured direct detection 0.95 / FP 0.00, in-page 0.45 / FP 0.024; spec 008 Completed.
- Spec 009: output guard and quarantine. Step type `output_guard` (run canary, active markup, heuristics, classifier: `canary_leak`, `injection_or_jailbreak`, `malicious_content`; codes only), `canary: true` on sessions over external content with validation that an output guard follows, per-run canary (`security.canary.rotate`); `handle_security_flag` flow (malicious_urls.jsonl via `SecurityLogPort`, deny-list once per domain with counter, inert quarantine via the vault tool `quarantine_note` with a write-protected quarantine folder, item state, alert) wired into triage, other resource and learning material; triage rows of flagged items are `quarantined`; owner release (UI + app MCP) restores the note, re-queues the item and exports a security eval candidate; output-guard eval set and gates (incl. `canary_leaks_unguarded = 0` for the 008 canary-leak regression), classifier rates per model, classifier cassette for CI; cassette keys normalise the run canary. The triage canary leak is real (4/150 in 10 live runs, all caught by the guard); one triage instruction line brought it to 0/150. Review fixes: validation also requires an `output_guard` to route on its decision (first conditional edge `<guard>.flagged`, no plain or error edges), so no wiring can write a flagged output; a release restores the note byte for byte (CRLF, no final newline); a domain deny-listed by the handler applies at once in the learning gateway (deny-list re-read per create) and in `learning.prepare`; an `Unsafe` label without a category is `malicious_content` (fail closed); the security e2e test checks that a released item is triaged again.
- Spec 010: category session plans. Step type `session_plan` runs the item's plan from `categories.json` (isolated sessions with declared inputs only, run canary, one span each; a session without its context pack is skipped); flow `other_resource` is now load plan -> secure fetch (when a session reads the page extract) -> sessions -> output guard -> note in the PARA folder (`<slug>-<id>.md`) -> processing list -> INBOX note archived (`4-Archive/Inbox`); public plans: Tool (research, compare, fit personal, fit enterprise, synthesize), Marketing (extract, synthesize), Misc (evaluate; a new-category suggestion becomes an agent task note); failed sessions, missing URLs and unreachable pages list the item as failed with the reason in the `link` column. Plan validation (`pkpipe.domain.session_plan`): no raw text or unvalidated output for a session with tools, no web search for the enterprise context or anything derived from it, instructions about 800 tokens, `note_session`; `security.query_guard` blocks private names in web queries. Overlay categories need no code. Sessions are eval targets (`datasets/sessions/<category>/<session>.jsonl`, 8 synthetic datasets, rubrics, cassettes), the flows suite has 5 new cases and 2 rewritten ones (21 in all) with scripted web pages.
- Repository skeleton, ports, triage domain rules, canary helper, layered config loader.
- Test speed (chore): the non-live suite runs in parallel with pytest-xdist (`uv run pytest -n auto -m 'not live'`, about 40 s instead of 2.5 min; per-worker data dirs and port blocks, live tests refused in xdist workers); eval request concurrency (`evals.concurrency`, `pkpipe eval --concurrency N`, default 1, live tests 4; dataset-order results, thread-safe cassettes, concurrent pairwise A/B); live eval tests share identical requests through a session cassette (`live_eval_cassettes`, auto mode), cutting the live eval tests from 53 to 36 minutes; `scripts/lmstudio-test-setup.sh` keeps model and judge loaded with no TTL and 4 parallel predictions.
- Test speed follow-up: unjudged live eval cases (10 of 42 judged) came from an LM Studio stall (judge produced 2 tokens in 25 min under memory pressure and a second client), each in-flight request timing out once with no retry. Model profiles get `retries` / `retry_backoff_s` (transient failures: connection, timeout, 5xx, 408/429, HTTP 400 "Model unloaded"; `model.retry` span events; the public pack retries twice), the live sessions test names its judge error, and `scripts/lmstudio-test-setup.sh` loads both models with a 32768-token context (`PKPIPE_LMSTUDIO_CONTEXT`).
