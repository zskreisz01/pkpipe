# Feature Specification: learning-gateway MCP and Process Learning Material

**Feature Branch**: `spec/012-learning-gateway`
**Created**: 2026-10-31
**Status**: Draft
**Input**: Design docs (`docs/`), process model (`docs/design/pkpipe-process-model.drawio`), constitution
**Companions**: [research.md](research.md) · [data-model.md](data-model.md)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Notebook and podcast from a URL (Priority: P1)

A learning item becomes a notebook with a podcast generated by local voices.

**Independent Test**: Flow test with the fake backend; live test with Open Notebook.

**Acceptance Scenarios**:

1. **Given** a learning item, **When** processed, **Then** a notebook is created from the URL and a podcast job starts
2. **Given** the job is ready, **When** polled, **Then** audio and link are stored and the list status is ready

### User Story 2 - Backend switch is configuration (Priority: P2)

The owner switches to NotebookLM without touching flows.

**Independent Test**: Contract tests against each backend.

**Acceptance Scenarios**:

1. **Given** `backend: notebooklm_browser`, **When** processing, **Then** the same tools are used

### Edge Cases

- Open Notebook down → failed with reason, retry next day.
- NotebookLM UI change → browser backend fails fast with a clear error.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Tools: `create(url, template)`, `status(job_id)`, `link(nb_id)`, `audio(job_id)`.
- **FR-002**: The notebook agent sees only URL and template (constitution IV).
- **FR-003**: Timeout configurable (default 90 min for local TTS); failure reasons recorded.

### Key Entities

- **NotebookJob**

## Success Criteria *(mandatory)*

- **SC-001**: Fake-backend flow covers ready, failed and timeout.
- **SC-002**: Podcast quality acceptable to the owner on 5 samples (manual).
